# pstack 手順（簡略版）

出典: cursor/plugins の pstack（MIT, Lauren Tan）を Claude Code 向けに要約。

## 0. 依頼の5要素
作業前に次を書き出す。欠けていたら質問して止まる。
1. 目的 2. 完了チェック（合否が出る形）3. 見せる証拠 4. 既知の情報 5. 制約

## 1. 種類ごとの手順
- **調査**（コードを変えない）: 調べる → 根拠（ファイル:行、コマンド出力）を添えて答える。
- **バグ修正**: 症状を**2回**再現する → 失敗するテストを書く（安く書ける場合）→ 根本原因を直す → テストが通る出力を貼る → 影響範囲（呼び出し元・似たコード）を確認する。修正の試行は1回。だめなら証拠を添えて止まる。
- **機能追加**: Plan mode で計画 → 了承 → 実装 → テスト → 動作確認の証拠（スクリーンショット・ログ）。
- **リファクタ**: 振る舞いを変えない。前後でテスト結果が同じことを示す。
- **大きい / 不明**: `docs/design/` に短い設計メモを書いて止まり、人間に確認する。

## 2. 共通
- 分岐点は `/worklog` に1行で残す。
- PR 前に `/interrogate` を通す。
- PR 本文に `## Goal`・`## Verification`（実際の出力）・`## Remaining` を書く。
- **eval gate**: マージ前に coordinator が evaluator（sonnet）と evaluator-opus（opus）を独立に走らせ、両方 PASS のときだけマージ。FAIL なら worker に差し戻し（最大2回）、それでも FAIL なら人間に報告。younap・お金・権限・本番 DB/D1 マイグレーションは常にマージしない。
- 終わったら AGENTS.md の報告4項目で報告する。
- 中断するときは、次の人が再開できるよう worklog に現状・次の一手を書く。
